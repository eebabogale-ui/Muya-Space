# Build a Modern Handyman Marketplace Platform for Addis Ababa

## 1. Product Overview

Build a production-quality full-stack web application that connects customers in Addis Ababa with verified local handymen/service professionals.

The platform should allow customers to:

* Find service providers
* Request a service
* Describe their problem
* Upload photos
* Set their location
* Choose a preferred time
* Receive offers/quotes from suitable handymen
* Compare handymen
* View handyman profiles and ratings
* Chat with handymen
* Book a handyman
* Track the job status
* Make payment
* Review the handyman
* Report problems or disputes
* Request emergency services

Handymen should be able to:

* Register and create a professional profile
* Select their skills/services
* Provide experience information
* Complete identity/phone verification
* Set service areas
* Set availability
* Receive nearby job requests
* Accept or reject requests
* Submit quotes
* Chat with customers
* Update job status
* Navigate to the customer location
* Complete jobs
* Track earnings
* Receive ratings and reviews
* Build a professional reputation

Administrators should be able to:

* Manage customers
* Manage handymen
* Verify handymen
* Manage service categories
* Monitor jobs
* Manage disputes
* Monitor payments
* Manage reviews/reports
* View analytics
* Suspend or deactivate accounts
* Manage platform settings

The initial launch location is Addis Ababa, Ethiopia.

The architecture must be designed so that the platform can later expand to other Ethiopian cities and potentially other countries without requiring a complete rewrite.

---

# 2. IMPORTANT DESIGN DIRECTION

The UI must look like a modern international technology startup.

DO NOT make the interface look stereotypically Ethiopian.

Do NOT use:

* Ethiopian flag colors as the primary UI palette
* Excessive green/yellow/red
* Traditional Ethiopian patterns
* Cultural decorations
* Overly colorful backgrounds
* Old-fashioned marketplace designs
* Excessive gradients
* Cheap-looking cards
* Cluttered dashboards
* Cartoon-style illustrations
* Excessive animations

The fact that the platform launches in Addis Ababa should NOT dominate the visual identity.

The product should feel like a modern global marketplace/SaaS application.

Design inspiration should come from modern products such as:

* Airbnb
* Uber
* Stripe
* Linear
* Vercel
* Notion
* modern SaaS dashboards
* modern service marketplaces

Do not copy their branding or UI directly. Use them only as references for quality, spacing, usability and visual sophistication.

---

# 3. VISUAL STYLE

Create a clean, premium, modern interface.

Use:

* Neutral/light backgrounds
* White surfaces
* Dark text
* One sophisticated primary accent color
* Subtle borders
* Soft shadows
* Large whitespace
* Rounded but not excessively rounded components
* Clear typography
* Strong visual hierarchy
* Consistent spacing
* Professional icons
* Responsive layouts

The design should feel:

* Trustworthy
* Premium
* Fast
* Professional
* Minimal
* Modern
* Easy to understand

Avoid making everything colorful.

Use color mainly for:

* Primary actions
* Status indicators
* Important notifications
* Success/error states
* Small visual accents

The UI should work beautifully on both desktop and mobile.

Mobile responsiveness is extremely important because many users will access the platform from phones.

# 8. HANDYMAN MATCHING

Create a matching system.

The system should consider:

* Service category
* Location/distance
* Availability
* Current workload
* Rating
* Experience
* Verification status

For normal jobs, suitable handymen should receive the request and be able to submit a quote.

For emergency jobs, prioritize:

* Currently available handymen
* Short distance
* Matching service
* Good rating

The matching logic should be modular so it can be improved later.

# 31. IMPORTANT MVP RULE

Do not over-engineer the first release.

The first usable version should prove one thing:

A real customer can request a service and successfully connect with a real handyman.

The minimum successful flow is:

Customer registers

→ chooses service

→ creates request

→ handyman receives request

→ handyman submits quote

→ customer accepts

→ handyman performs job

→ job marked completed

→ customer reviews handyman

Everything else should support this core loop.

---

# 36. BEFORE CODING

Before implementing the entire application:

1. Analyze the requirements.
2. Propose the technology stack.
3. Propose the database schema.
4. Propose the application architecture.
5. Propose the folder structure.
6. Identify any important ambiguities.
7. Create the initial UI shell.
8. Then implement the MVP incrementally.

Do not silently make major architectural decisions that conflict with these requirements.

If there is a better technical approach, explain it briefly and use it.

---

# 37. MOST IMPORTANT PRODUCT PRINCIPLE

This should not feel like a school project.

Build it as if it could eventually become a real company.

The application should communicate:

"Find a trusted professional to solve your problem."

It should feel trustworthy, fast, modern and professional from the first screen.

The visual design should be internationally modern, not culturally themed.

Launch market:

Addis Ababa, Ethiopia.

Future:

Expand to other cities and countries.

Start with a strong MVP, but keep the architecture ready for growth.
